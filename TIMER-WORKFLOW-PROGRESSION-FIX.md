# Timer Workflow Progression Issue - Root Cause Analysis and Fix

## Issue Summary
Timer workflows execute the first task and sleep task correctly, but fail to progress to dependent tasks after the timer completes. All tasks remain in "pending" status despite successful timer execution.

## Root Cause Analysis

### Investigation Timeline
1. **Initial Problem**: Timer workflows not progressing through all 3 tasks (start_task → sleep_task → end_task)
2. **Secondary Issue**: RUNNING enum conversion errors during workflow progression checks
3. **Deep Investigation**: Timer mechanism analysis revealed event consumption gap

### Technical Analysis

#### ✅ Working Components
1. **TimerMonitorService**: Correctly processes expired timers
   - Location: `/src/gleitzeit/timers/monitor.py`
   - Function: Monitors `timers:pending` sorted set, triggers expired timers
   - Evidence: Timer `workflow-61f1e323:task-0071b4a4:03042b37` moved to `timers:completed`

2. **Timer Registration**: Properly stores timer metadata in Redis
   - Location: `/src/gleitzeit/timers/handler.py:90-94`
   - Evidence: Timer metadata stored correctly with wake_at timestamp

3. **Event Generation**: TASK_COMPLETED events created and stored
   - Evidence: Event found in stream `gleitzeit:events:stream:task:completed` at `1757671126412-0`

4. **Event Consumer**: StreamEventBus running with consumer group
   - Evidence: `Starting event consumer for consumer_63cff2a1`

#### ❌ Root Issue: Event Consumption Gap
The TASK_COMPLETED events generated by TimerMonitorService aren't being consumed by TaskOrchestrator to update task statuses and trigger workflow progression.

**Specific Problem**:
- TimerMonitorService sends events to: `gleitzeit:events:stream:task:completed`
- TaskOrchestrator needs to consume these events but isn't processing timer-originated events
- Result: Task status remains "pending" instead of updating to "completed"
- Consequence: Dependent tasks never get triggered

### Evidence from Logs
```

```
- Timer triggered successfully

  "id": "task-0071b4a4",

- Task status unchanged despite timer completion

## Technical Fix Required

### Problem Location
- File: `/src/gleitzeit/timers/monitor.py:192`
- Issue: Events sent to stream but not consumed by workflow progression logic

### Solution
The TaskOrchestrator needs to properly handle TASK_COMPLETED events from timer sources to:
1. Update task status from "sleeping" to "completed" 
2. Trigger evaluation of dependent tasks
3. Continue workflow progression chain

### Implementation Plan
1. Ensure TaskOrchestrator subscribes to timer-generated TASK_COMPLETED events
2. Add proper event handler for timer completion events
3. Update task status tracking for timer-based completions
4. Test end-to-end workflow progression
